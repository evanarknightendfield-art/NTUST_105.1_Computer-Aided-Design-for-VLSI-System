# Lab3 解法比較：v1、v2、v3、CodexGapSA、CodexParetoDP，以及離最佳解還有多遠

| 版本 | 資料夾 | 一句話 |
|---|---|---|
| v1 | `ClaudeOpus55/` | Abacus + 位移微調（insert / swap / evict）＋ SA（optimal region、range limiter） |
| GapSA | `CodexGapSA/` | （Codex，獨立實作）寬 cell 優先放進最近的空隙、雙 cell 修整 ＋ SA（60% 時回到最好解重啟一次） |
| v2 | `ClaudeOpus55_v2/` | v1 + 同寬匹配、每 row 精確重排、流量式 spreading（自動選）＋ SA 補救 move、local reordering |
| ParetoDP | `CodexParetoDP/` | （Codex，以 v2 為底）+ 總位移不增加的瓶頸匹配 ＋ SA 之後的確定性下降（滑動、跨 row 搬移／交換、ISM、三顆排列） |
| v3 | `ClaudeOpus55_v3/` | v2 + 最後幾輪精確重排、SA 低溫時的 linear placement（講義 L07）與 independent set matching、net box 快取、依大小給 SA 次數 |

11 筆測資（課程 3 筆 + `Testcases/holdout` 8 筆），每個版本都用 `Grader/tools/local_grade.py` 跑
（打包 → 重新編譯 → 執行 → 獨立檢查器），**55 次全部 PASS**。各版本用**自己的預設參數**、seed 1、單執行緒；
粗體 = 五個版本裡最好的。

### 兩個 Codex 版本各自的特色

| | 優點 | 弱點（這次的數據） |
|---|---|---|
| GapSA | 獨立寫的，程式短（約 600 行）、最快；寬 cell 先放可以減少空隙被切碎；有 sanitizer 回歸測試 | 一次放一個 cell 到「最近的空隙」、不會推動已放好的 cell → 擁擠處總位移 1.6 倍、最大位移 1.8 倍；SA 次數少，HPWL 比 v1 差 28% |
| ParetoDP | 匹配有**數學保證**：在「總位移不增加」的前提下求最小的最大位移（二分 + Hungarian），比 v2 的懲罰函數好解釋；SA 之後的確定性下降每一步都只接受變好 | 在 v2 上加的位移改善很小（0.1% 左右）；預設次數跟 v2 一樣，HPWL 跟 v2 差不多（0.948 vs 0.947） |

v3 可以借鏡的：ParetoDP 的「總位移預算下的瓶頸匹配」比 v2 / v3 的 φ 懲罰更乾淨（保證不變差），
可以直接取代 v3 的 `reduceMaxByMatching`；GapSA 的「寬 cell 優先」可以拿來當 Abacus 之外的另一個初始解。

## 3. 離最佳解還有多遠

### Stage 1：用精確模型算下界 / 最佳解（`Grader/tools/exact_bound.py`）

把合法化寫成精確的整數規劃：每個 cell 一個「放在哪個 row 的哪個 site」的 0/1 變數，每個 site 最多被一個 cell 蓋住，
目標 = 總位移。它的 LP 鬆弛（column generation 解到最佳）是**保證成立的下界**；小設計可以直接解整數規劃得到**最佳解**。
`--cap` 只允許位移 ≤ 該版本自己的最大位移，比的是「**最大位移一樣的前提下，總位移最低能到多少**」（公平，因為不限制的話，
總位移最佳解的最大位移會大很多：h01 的總位移最佳解最大位移是 51.6，我們是 31.7）。

| bench（cells） | 版本 | 我們的總位移 | 同樣最大位移下的最佳 / 已知最好 | 我們高出 | 最大位移下界 | 我們的最大位移 | 高出 |
|---|---|---:|---:|---:|---:|---:|---:|
| toy（31） | v1 | 46,619.2 | 43,108.6（最佳） | 8.1% | 1,962.4 | 1,987.6 | 1.3% |
| toy | v2 / v3 | 44,375.6 | 42,890.2（最佳） | 3.5% | 1,962.4 | 2,007.9 | 2.3% |
| h01（300） | v1 | 2,575.6 | 2,356.6（最佳） | 9.3% | 30.5 | 33.1 | 8.4% |
| h01 | v2 / v3 | 2,528.1 | 2,383.6（最佳） | 6.1% | 30.5 | 31.7 | 3.9% |
| h02（1000） | v2 / v3 | 526,484 | 487,184（10 分鐘內找到的最好解；下界 462,963） | 8.1%（離下界 13.7%） | — | 2,607.3 | — |

（不限制最大位移時，toy 的總位移最佳解是 42,106.4，h01 介於 2,235.4 ~ 2,256.9。）

再往下看 h01 的最佳解跟我們差在哪：300 個 cell 裡只有 21 個在不同的 row、同一 row 的順序只差 6 對，
**差距來自少數幾個 cell 一起換 row**（例如 A 從 row 3 到 row 4、B 從 row 4 到 row 3，兩邊的鄰居一起挪），
一次只動 1 ~ 2 個 cell 的 local move 找不到。v3 試了「交換 + 推擠」（`--swappush`）抓這種 move，結果有好有壞、慢 1.7 倍，所以預設關掉。

大設計（ibm01、ibm05、h03 以上）LP 太大，算不出有意義的界；bin 版的鬆弛（`lower_bound.py`）又太鬆（只到 1.4 ~ 2 倍），不能拿來判斷。

### 所以，是不是已經最佳？

| 指標 | 判斷 | 根據 |
|---|---|---|
| 最大位移 | **小設計接近最佳**（離下界 2 ~ 4%） | toy、h01 有證明過的下界；大設計（ibm01、h08 熱點很嚴重）沒有界，而且三個版本都幾乎沒動，是最難的部分 |
| 總位移 | **還有 3.5 ~ 8% 的空間**（同樣最大位移下） | toy、h01 的最佳解，h02 的已知最好解 |
| HPWL | **還沒收斂**，多花 2 ~ 4 倍時間可以再降 0.5 ~ 4% | 長時間的實驗；沒有理論下界 |

## 4. 還能改良的地方（依我認為的效益排序）

1. **SA 多執行緒**（HPWL）：ABCDPlace 的做法，把晶片切成互不影響的區塊同時做 move，4 ~ 8 核大約等於 4 ~ 8 倍次數，
   照上面的實驗大約再降 1 ~ 4%，而且時間不變。需要處理不同區塊共用的 net（只在區塊內部的 net 才平行）。
2. **多個 cell 一起換 row**（總位移）：精確解顯示差距來自少數 cell 一起換 row。可以做
   - RippleLG 的 MGL：在一個多 row 視窗裡用位移曲線找最佳插入點（取代 Abacus 的「只往最右邊加」）；
   - 或在小視窗裡做真正的最佳化：視窗內 20 ~ 50 個 cell 的 site 層級指派，用自己寫的 branch & bound 或 min-cost flow 近似。
3. **真正的流量式合法化**（熱點設計的最大位移）：ISPD'17 的方法在 bin 之間搬移後，還要**在 bin 裡面**合法化並遵守 bin 的分配；
   v2 / v3 只拿 spreading 的結果當 Abacus 的目標，Abacus 可能又把 cell 推出 bin，所以效果有限（ibm01 的最大位移三個版本都在 10,6xx）。
4. **Window interleaving**（講義 L07，Hur & Lillis ICCAD'00）：一個視窗內兩組 cell 保持各自順序、用 DP 找最好的交錯方式，
   比 3 個 cell 的 local reordering 範圍大。
5. **自適應溫度**（Lam 的 schedule）：讓接受率照固定曲線下降，不用手調 p0、tEnd。
6. **時間**：v3 是 v1 的 2 ~ 5 倍。如果評分有時間限制，`--effort 2000` 大約回到 v2 的時間（HPWL 少降約 0.5 ~ 3%）。
