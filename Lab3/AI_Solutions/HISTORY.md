# Lab3 解法演進：v1 → v6（含 Codex 各版）

從 v1 到 v6 共 11 個版本（Claude 6 個、Codex 5 個）。每一版做了什麼、解決了什麼、進步多少。
進步主要來自三次跳躍：**v2 的總位移與最大位移、v4 的大設計跑得動、ChainDP 的最大位移**；v5 之後主要是時間分配與穩健度。

**數據來源**

- v1 ~ v4（含 GapSA、ParetoDP、WindowDP）：[COMPARISON.md](COMPARISON.md) 第 1 ~ 4 節，當時同一次量的。
- ChainDP、v5、CodexCapDP、v6：2026-10-22 同一段時間、同一台機器的配對重跑
  （[v6 診斷](../Testcases/results/ClaudeOpus55_v6/diagnosis.md)、[v6 最終驗證](../Testcases/results/ClaudeOpus55_v6/final/summary.md)）。
- 兩批不是同一次執行；跨批比較只看大方向。數字都是越小越好。
- 版本關係：GapSA 是 Codex 的獨立實作；ParetoDP 以 v2 為底；其他都以前一版為底。
- v2、v3、GapSA、ParetoDP 的原始碼已移除，在 git commit `e1fd81f`。

## 6. 每一版改了什麼、解決了什麼

| 版本 | 主要改動 | 解決的問題 | 留下的問題 |
|---|---|---|---|
| v1 | Abacus 合法化 + insert / swap / evict 位移微調 + SA（optimal region、range limiter） | 建立可用的基準（教學參考解） | 大設計慢（L1 38 分鐘、L2 跑不完）；沒有可移動 cell 時當掉 |
| GapSA | 寬 cell 優先放進最近的空隙、雙 cell 修整 + SA（60% 時回到最好解重啟） | 驗證另一條路 | 全面比 v1 差，已移除 |
| v2 | 同寬匹配、每個 row 精確重排、流量式 spreading（自動選）、SA 補救 move、local reordering | 最大位移 −5.2%、HPWL −5.3%、總位移 −2% | 之後四個版本的最大位移都卡在同一個值 |
| ParetoDP | 總位移不增加的瓶頸匹配、SA 之後的確定性下降 | 幫助很小（總位移 −0.1%） | |
| v3 | 最後幾輪精確重排、SA 低溫時用 linear placement 與 independent set matching、依大小給 SA 次數 | HPWL −2.1% | site 寬度不同時 SA 換出不合法的解 |
| WindowDP | 兩個 row 的子集合 DP（視窗內精確）、同 row 的精確 HPWL 排序 DP | 總位移 −3.7%；修 v3 的 bug；找出下界工具 `exact_bound.py` 的三個 bug（之前「離最佳 2 ~ 4%」的說法是錯的） | 大設計仍要 56 分鐘 |
| v4 | DP 掃到收斂、三個 row 的 DP、多執行緒 SA 與 DP、每個階段都有時間預算、Abacus 與 max pass 改成近線性 | 總位移 −6.4%（11 筆全部最好）；大設計 56 分鐘 → 3 分鐘、L2 跑得完 | 最大位移離最佳還差 18%（h01） |
| ChainDP | 最大位移的全域上限修復（site 擁擠協商）、ejection chain、多候選 global / vertical swap | 最大位移 −4.2%（對 v4），總位移持平 | Stage 1 多花 4 + 16 秒，同總時間 HPWL +1.5% |
| v5 | SA 用滿時間（每步次數可調回）、平行 merge 只算一次、row 重新分配 + row 內精確壓緊的最大位移搜尋、額外步驟固定 6 / 12 秒 | 同總時間 HPWL 1.015 → 0.991（÷ v4）；toy 到精確取捨曲線上的點 | 10/27 筆最大位移比 ChainDP 差 |
| CodexCapDP | 違規 cell 周圍的局部上限視窗修復、修復後 DP 限縮範圍、修正 memo 失效範圍、保留有潛力的候選續跑、≥ 50 萬 cell 改 SA30 → polish60 | 11 筆雙條件 6/11 → 9/11 | e07 額外時間超出；L2 的時間分配依 cell 數寫死 |
| v6 | 修復迴圈每步看時間、polish 依收穫決定次數（放不下的 pass 不開始）、SA 量自己的效率（每 cell < 100 次就讓時間給 polish）、大設計 SA 4 執行緒 | L2 HPWL −4.9%（對 CodexCapDP）、−7.5%（對 v5）；額外步驟超時 1/27 → 0/27 | 最大位移 5 筆仍輸 ChainDP；同總時間 edge HPWL 差 0.28% |
| CodexParallelChain | 平行 SA band 分界四相輪替；target/ejection/cap deadline 候選撤回 | 27 筆雙條件 20/27；同總時間、預設 HPWL 的 holdout/edge 平均均不差於同輪 v6 | 27 筆有 7 筆、新 seed 有 5 筆未達雙條件；逐筆差距見 README；逐筆最大對 v6 變動門檻未由 summary 證實 |
| v7 | Stage 1 的 pipeline 用完份額（這台機器上做不完）時跳過 final rounds，時間給 pareto + 視窗 DP；細期限檢查；pareto 平行且第一輪一定跑；自動 8 個 worker（SA 受記憶體上限時 ≤ 可用 CPU）；final rounds 的視窗 memo 交給後面的 DP；cap 搜尋依量到的超時量決定是否開始 | L2 總位移 −4.7%、最大 −7.3%、HPWL −1.0%、快 16 秒；pareto 的牆鐘斷崖（晚 1 秒 HPWL +7%）消失；L2 額外步驟不再超時；L1 總位移 −0.7%（真 2 核 −7.7%）；同總時間 HPWL holdout / edge −0.02% / −0.12%；新 seed 雙條件 12/16 | 27 筆雙條件 20/27（e15 總位移超上限 0.04%）；預設參數 HPWL holdout / edge +0.03% / +0.10%；L1 HPWL 全核 +0.09%、真 2 核 +1.26%（DP 壓位移、legal HPWL 變高）；h06 最大位移仍雙峰 |
