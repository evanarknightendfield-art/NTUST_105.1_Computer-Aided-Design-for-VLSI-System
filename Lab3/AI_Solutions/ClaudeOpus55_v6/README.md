## 2. 改了什麼（相對 CodexCapDP，`diff -r` 只有這些）

1. **時間保證**（`capsearch.cpp`）：`rowRepair` 的 phase 1、phase 2 每一步都看時間（原本每 256 步）。e07 的額外時間 6.21 → 4.10 秒，最大位移相同、總位移 19777 → 19772。
2. **polish 次數依收穫**（`optimizer.cpp/.hpp`）：前 3 個 pass 照舊；第 4 個起只在上一 pass 仍降 ≥ 1% 時繼續；**放不下的 pass 不開始**（一個 pass 不能中斷，v5 的 30 秒 polish 在 L2 用了 34 秒）。L1 的 pass 只降 0.15~0.9%，行為與 CodexCapDP 相同。
3. **SA 依量到的效果決定時間**（`annealer.cpp/.hpp`、`main.cpp`）：取代 CodexCapDP「≥ 50 萬 cell 就 SA30→P60」的寫死規則。
   平行 SA 在第 0 步量速度，換算整個時間上限能給每顆 cell 幾次嘗試；**少於 100 次就只留 10% 的時間，其餘交給 polish**（`--sa-starved A` 可調，0 = 關；明確給 `--time` 時預設關）。
   依據（同一 L2 起點，sa_bench，2 seeds）：SA 0 / 7 / 15 / 30 / 45 / 60 秒（其餘 polish）→ HPWL 1.545 / 1.546 / 1.569 / 1.616 / 1.693 / 1.802e9；
   L1（每顆約 375 次）SA 15 / 30 / 45 / 60 → 2.17 / 1.90 / 1.79 / 1.736e9。比例式的縮短無法同時照顧兩者，所以用門檻（L2 ≈ 45~60 次 → 6 秒；L1 不動）。
4. **大設計 SA 執行緒**（`annealer.cpp`）：記憶體規則的下限 2 → 4、上限 8e6/n → 12e6/n。L2 從 2（或 3）個執行緒變 4 個：同起點 SA30→P60、2 seeds，attempts +29%、HPWL −0.83% / −0.73%。200k cell 以下的設計不受影響。

Stage 1 的最大 / 總位移搜尋、chain、平行 SA 的移動與 merge 都沒改。

## 6. 還沒做到

1. 最大位移：e03（預算）、h04 / e12（修復品質）、h07 / h06（時間）。要達到 ChainDP 的值，現有方法需要 ChainDP 的 1.01 比例與約 20 秒（第 1 節），在 6 秒內做不到；精確子問題也不可行。
2. 總位移：e08、e16、e15（以及 seed5 的 e05 / e08 / e10 / e16）——這些筆的最大位移都比 ChainDP 低 4~21%，是「花總位移換最大位移」的取捨，驗收標準是逐筆對 ChainDP。
3. L2 的 Stage 1 起點每次不同（同一 binary 兩次 SA 前 HPWL 2.82e9 vs 2.64e9），大設計 HPWL 的單次比較要看同起點的控制實驗。
