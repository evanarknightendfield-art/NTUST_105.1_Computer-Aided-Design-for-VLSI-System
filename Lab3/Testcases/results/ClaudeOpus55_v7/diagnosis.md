## 3. Stage 1 的時間花在哪（第一階段 3）

### 3.1 中小設計（27 筆）：尾巴不是浪費，重解才是

`phase1/analysis/dpcurve.md`（插樁版 `--trace-dp`）。span = 選定 pipeline 之後的 final rounds + pareto + 主視窗 DP，27 筆共 181.9 秒。

| 若在「總位移 ≤ 最終 × (1+ε)」時就停 | ε = 1e-3 | 3e-4 | 1e-4 |
|---|---:|---:|---:|
| 27 筆可省秒數 | 33.0 | 22.4 | 16.9 |
| 訓練 11 筆可省秒數 | 13.8 | 8.8 | 6.7 |

- 主要設計的尾巴收穫並不低：h06 最後 20% 的 span（3.7 秒）總位移 −2.73%、h08 −1.16%、h04 −0.75%、h07 −0.65%（final max pass 先把總位移推高，之後的 DP 再收回）。
  依收穫提早停只能省約 17 秒，而且會改變 cap 搜尋的起點。
- 可省的秒數大多不是 DP 尾巴，而是**主視窗 DP 重解**：pareto 之後的 `windowSweeps(stage1Memo)` 用一份新的 memo，finish() 內的 memo 是區域變數，
  所以 finish() 已經解過、沒變的視窗全部重解。27 筆主 DP 共 32.4 秒；e01 / e04 / e06 / e07 / e11 / h01 / h05 0 改善仍花 0.12–1.11 秒（e01 解 10,823 個視窗、0 改善）；
  h08 解 94k 個視窗 5.1 秒（改善 4.2k 個）。memo 的設計本來就能處理中間被其他演算法改過的 cell（`WindowMemo::sync`），共用之後結果應相同、只少做沒變的視窗。
- 兩條 pipeline（plain / spread）27 筆各自贏的次數差不多（plain 12、spread 13），不能省。

## 7. 第二階段計畫
