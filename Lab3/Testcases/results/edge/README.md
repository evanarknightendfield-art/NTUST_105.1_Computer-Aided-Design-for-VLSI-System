# edge 測資的結果：有沒有過擬合

各版本的參數是在課程 3 筆 + holdout 8 筆上調的。這 16 筆（`Testcases/edge/`，說明在 `Testcases/README.md`）是那 11 筆
**沒出現過的情況**，用來看「好」是不是只在原本的測資上成立。全部用 `Grader/tools/local_grade.py`、各版本預設參數跑
（`../run_edge.sh`）；「參考合法解」是 `gen_edge.py` 產生每筆測資時先排好的合法 placement，是一個已知可行的答案。

重建這份表：`python3 make_table.py > tables.md`。完整輸出在 `../local_grade/edge_<版本>/`（不進 git）。

## 結論

**1. 穩健度：找到兩個舊版本的 bug**

| 版本 | 問題 | 原因 |
|---|---|---|
| v1、v2、v3 | `e14_fixedonly`（沒有可移動的 cell）**segfault，沒有輸出** | 合法化之後找「位移最大的 cell」時直接讀 `movable[0]`，陣列是空的。CodexParetoDP 修過，WindowDP、v4 繼承了修正 |
| v3 | `e10_mixedsites`（row 的 site 寬度 2、3 交替）**整個 Stage 2 白做**：HPWL = 合法化的 1,232,694，其他版本約 800,000 | SA 的 independent set matching 只比「佔幾個 site」，把實際寬度 6 和 9 的 cell 互換 → SA 的結果不合法 → 程式的保護機制退回 Stage 1 的結果。WindowDP 補上了實際寬度和 site 寬度的檢查，v4 繼承 |

其他 7 個版本 16 筆全部通過（包括 CRLF、`terminal_NI`、1-pin net、晶片外的起點、不等距的 row）。

**2. 品質：v4 的排名沒有因為換測資而改變，但領先幅度變小**

| ÷ v1 幾何平均 | 原本 11 筆 | edge 16 筆 | 說明 |
|---|---:|---:|---|
| 總位移：v4 vs WindowDP | 0.875 vs 0.935（−6.4%） | 0.925 vs 0.957（−3.3%） | 7 個正式版本裡 v4 每一筆都最好或並列（以 v4 為底、進行中的 ChainDP 再好 0.4%）；但幅度只剩一半：原本的測資熱點很多，最適合 DP 發揮 |
| 最大位移：v4 vs 其他 | 0.947 vs 0.948 | **0.900** vs 0.969 | edge 上反而差更多：e06（800 個窄 row）41.7 vs 105.7，三個 row 的 DP 在窄 row 上特別有用 |
| HPWL：v4 vs WindowDP | 0.920 vs 0.927（−0.8%） | 0.896 vs 0.899（−0.3%） | **幾乎沒差，在雜訊內**。v4 的 HPWL 優勢來自 8000 cell 以上的平行 SA（e01 −2.9%、e16 −2.1%）；小設計跟 WindowDP 互有勝負 |

**3. 還有的弱點**

- `e01_nearlegal`（像真的 global placer 的輸出）：**所有版本**的最大位移都是 5.595，比參考合法解的 5.4 差 3.6%。
  表示就算是簡單的情況，最大位移也沒有最佳化到底（跟 `AI_Solutions/COMPARISON.md` 第 4 節 h01 的結論一樣）。總位移則比參考解少 14%。
- `e07_tworows`（只有 2 個 row）：v4 的 HPWL 比 v2 差 3.5%、比 WindowDP 差 2.9%；換 4 個 seed 平均，v4 197,479、WindowDP 193,999（+1.8%，
  兩者 seed 之間的差距 190k ~ 208k）。只有兩個 row 時三個 row 的 DP 用不到，SA 也不能上下移。
- `e04_sparse10`（1404 個 cell、很空）：v4 要 14 秒，v3 3.6 秒。≤ 1500 cell 用的大視窗在很空的 row 上很長，DP 變慢（結果只好 0.4%）。
- 原本的 HPWL 優勢不能當成「v4 的 SA 比較好」：同樣的 SA（單執行緒）在 edge 上跟 WindowDP 差不多。
