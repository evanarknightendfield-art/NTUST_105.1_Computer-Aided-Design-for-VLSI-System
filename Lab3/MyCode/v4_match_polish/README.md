# v4 — 往最終版過渡：匹配、位移不變交換、polish

> v3 和加速最終版（v5）差很多，尤其 HPWL（L2 差將近一倍）。加速最終版約 1 萬行、多執行緒，這一版從裡面挑出**三個獨立、好解釋、效果大**的想法，
> 用 v3 的資料結構自己重寫（約 +400 行），再讓 SA 用滿時間：
> (1) 同大小 cells 的最小成本匹配、(2) **位移不變的 HPWL 交換**、(3) SA 之後依位置掃的 polish。
> 和 v3 比：HPWL ibm01 −8.8%、L1 −16%、L2 −24%；總位移 −1 ~ −4%；最大位移持平。四筆都 ≤ 48.1 秒。
> 拿掉每一項來看：ibm01 的進步來自 SA 用滿時間，L1、L2 的進步來自位移不變交換；匹配和 polish 的貢獻都在 1 ~ 2% 以內。

## 編譯與執行

```bash
cmake -S . -B build
cmake --build build
./build/dp INPUT_FILE OUTPUT_FILE [options]
```

和 v3 一樣，另外多了：

| 選項 | 說明 |
|---|---|
| `--no-match` | 不做同大小 cells 的匹配 |
| `--no-nswap` | 不做位移不變的 HPWL 交換 |
| `--polish-share F` | SA 時間的最後幾成給 polish（預設 0.15；0 = 不做） |
| `--polish-only-below K` | 時間只夠每個 cell 做不到 K 次 move 時不做 SA、全部給 polish（預設 0 = 一律做 SA；試過，比較差） |
| `--effort K` | 預設改成 20000（v3 是 2000），實際由時間決定 |

## 和 v3 相比改了什麼

```
讀檔 ─ Abacus ─ 微調 ─ (1) 匹配 ─ (2) 位移不變交換 ─ SA ─ (3) polish ─ 寫檔
                       └─ 新的 ─┘                         └ 新的 ┘
```

| 改動 | 檔案 | 來源 |
|---|---|---|
| **(1) 同大小 cells 的最小成本匹配** | `improve.cpp` 的 `matchSameSize` | 講義 L07 用 matching 做合法化；最終版的 pareto matching |
| **(2) 位移不變的 HPWL 交換** | `improve.cpp` 的 `neutralSwap` | 最終版的 neutral swap（`nswap.cpp`） |
| **(3) polish** | `annealer.cpp` 的 `polish`、`proposeAt` | 最終版 Stage 2 最後的確定性 polish |
| **SA 用滿時間** | `annealer.hpp` 的 `movesPerCell` 2000 → 20000 | v3 的 ibm01 SA 12 秒就做完了，期限還剩 38 秒 |

時間分配（每一步都是「當下剩下的時間」的幾成）：Abacus 之後，微調最多 30% → 匹配最多 10% → 交換最多 50% → 剩下的 SA 用 85%、polish 15%。
每一步都是「做到收斂或時間到」，提早結束的時間留給下一步。

### (1) 同大小 cells 的最小成本匹配

**想法：** 寬、高都一樣的兩個 cell 互換位置，placement 一定還是合法（佔的格子完全一樣）。所以一群同大小的 cells 和它們現在佔的位置，可以任意重新分配。
Abacus 和微調都是一個一個 cell 貪心決定的，重新分配可以找到總位移更小的組合。

```
把同大小的 cells 依位置排序，每 16 個一組
每一組：cost[i][j] = cell i 放到第 j 個位置的位移（超過目前最大位移的設成不准）
        Hungarian 找總 cost 最小的指派（O(16³)）；比現在好就換
4 輪：「先 row 再 x」「先 x 再 row」各一次，再錯開半組各一次（組的邊界不一樣）
```

目前的排法一定可行，所以結果只會更好；位移超過上限的配對不准，所以最大位移不會變大。

### (2) 位移不變的 HPWL 交換

**想法：** 總位移 Σ |x − gx| + |y − gy| 在很多方向是平的。例如兩個同大小的 cell，GP 都在兩個位置的左邊，交換後一個多走 d、一個少走 d，總和不變。
匹配和微調只挑了其中一個解，完全不看 net；這一步從這些「位移一樣好」的解裡挑 HPWL 小的。

```
每個 cell a（依位置掃，奇數輪反過來）：
    a 的 optimal region 中點、a 和它的中間、a 自己 → 這 3 個點附近（上下各 1 個 row），
    每個 segment 裡同大小的 cells 左右各 3 個當候選 b
    條件：交換後總位移沒有變多、兩個都不超過最大位移
    HPWL 變化：a 的 net（b 不在上面的）+ b 的 net（a 不在上面的）；兩個都在的 net 不會變
    換 HPWL 少最多的那個
一輪的收穫不到第一輪的 2% 就停
```

**快速算 HPWL 變化：** 每條 net 記 x、y 方向的最小、次小、最大、次大（和是誰），「去掉 a 之後的 bounding box」O(1) 就知道，不用每次掃整條 net。

### (3) polish

SA 結束（倒回 best）之後，**依位置**掃過每個 cell，目標點 = 它的 optimal region 裡離自己最近的點、region 的中心，兩個都試（用 SA 的 `proposeAt`：空位就搬、有 cell 就交換），
HPWL 變小才做。SA 是隨機挑 cell，大設計（100 萬 cell）的記憶體存取很分散；依位置掃比較快，也保證每個 cell 都被看過。

## 觀察

- **位移不變交換是最大的一項：** L1 的 legal HPWL 少了一半（5.27e9 → 2.47e9），而總位移還少了 3%。
  L1、L2 只有 13 種 cell 大小（每種上萬到十幾萬個），同大小的 cells 很多，Abacus 依 x 排序放進 row 時，「同大小的誰放在哪個位置」對位移常常沒差，對 net 卻差很多；
  v3 的 SA 每個 cell 只有幾十 ~ 兩百次 move，來不及把這些亂掉的順序排回來，交換直接在 Stage 1 就排好了。
- **ibm05 沒變好：** ibm05 的 SA 在 v3 已經用滿時間（每個 cell 約 2000 次 move），legal HPWL 好 5% 的起點在 SA 之後就看不出來了。
  ibm01 的進步主要來自 SA 用滿時間（見上面的對照）。
- **和 v5（加速最終版）還差多少：** HPWL ibm01 54.7M vs 49.2M、L1 2.21e9 vs 1.78e9、L2 1.97e9 vs 1.37e9；總位移 L1 3.99e9 vs 2.44e9。
  剩下的差距來自最終版的視窗 DP（幾個 row 一起精確重排位移）、多執行緒 SA / polish、最大位移的全域修復等，見 [v5](../v5_final/README.md)。
