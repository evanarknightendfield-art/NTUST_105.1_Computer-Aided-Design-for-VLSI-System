# v3 — 位移微調 + 全程 60 秒（Milestone 5 + 10/28 規定）

> 兩件事：(1) TUTORIAL Milestone 5 的**位移微調**（insert / swap / evict），ibm01 最大位移 17,783 → 10,578、總位移 −26%；
> (2) 10/28 規定**每筆 60 秒（含讀寫檔）**：整支程式有一個 50 秒的期限，Abacus 加速、微調和 SA 都從剩下的時間分。
> **第一個四筆（ibm01、ibm05、L1、L2）都合法而且 ≤ 60 秒的版本**；ibm-place2 的 16 筆也全部通過（≤ 49.4 秒）。

## 編譯與執行

```bash
cmake -S . -B build
cmake --build build
./build/dp INPUT_FILE OUTPUT_FILE [options]
```

| 選項 | 說明 |
|---|---|
| `--deadline SEC` | **整支程式**（讀檔 + 兩個 stage + 寫檔）大約在 SEC 秒內結束（預設 50，離 60 秒留 10 秒） |
| `--refine-share F` | Abacus 做完後，微調最多用剩下時間的幾成（預設 0.3） |
| `--time SEC` | SA 時間上限（預設：期限剩下多少就用多少） |
| `--no-refine`、`--no-evict` | 關掉微調 / evict（比較用） |
| `--exact-work W`、`--exact-cells N` | Abacus 的 (b) cost：前 W 次 cell 走訪照算（1e9），之後只有合併 ≤ N 個 cell 才照算（16） |
| `--p0-low K P` | 時間只夠每個 cell 做不到 K 次 move 時，p0 改成 P（500、0.05） |
| 其他 | 同 v2（`--effort`、`--seed`、`--trace`、`--p0`、`--target`、`--win0`、`--minwin`…） |

不限時間跑（例如做 effort 曲線）：`--deadline 1e9 --time 1000`。

## 和 v2 相比改了什麼

### (1) 位移微調（`legalizer.cpp` 的 `Refiner`）

Abacus 是貪心的（x 小的先挑），最大位移集中在熱點。合法之後再做兩種 local move，每次都檢查「動到的 cell 位移不能超過上限」：

| move | 做法 |
|---|---|
| **insert** | 把 c 拿起來插到某個 segment 的某個 site，左右鄰居各自往外推「剛好夠」的距離；被推的 cell 往自己目標靠近可以隨便推，遠離的話不能超過上限 |
| **swap** | c 和 b 交換（b = 那個 row 裡蓋住 c 的 GP 中心的 cell），各自放得進對方的空間（`RowMap::freeAround`） |
| **evict** | 最大的 c 自己動不了時：c 目標附近找一個位移很小的 b 拿出來，c 放進 b 的位置，b 再去找別的地方（找不到就全部還原） |

```
重複最多 4 輪：
    reduceMax：反覆拿位移最大的 c，上限 = 目前最大值 − 1 個 site，找得到 insert / swap 就做，
               找不到就試 evict；都不行就停 → 最大位移只會下降
    reduceTotal：每個 cell（位移大的先）試 insert / swap，總位移變小、而且不超過目前最大值就做
    最大位移沒再下降就停（reduceTotal 會空出位置，reduceMax 下一輪又能用，所以交替）
```

### (2) 全程 60 秒

v2 只限制 SA 40 秒，其他部分多久算多久：L1 已經 50 秒，L2 的 Abacus 300 秒跑不完。v3 的時間安排：

```
讀檔 ─ Abacus ─ 微調（剩下時間 × 0.3）─ SA（剩下的全部）─ 檢查 + 寫檔（預留 0.5 + 1e-6 × (nodes + nets) 秒）
└──────────────────────────── 全部在 --deadline（50 秒）內 ────────────────────────────┘
```

| 改動 | 為什麼 |
|---|---|
| **Abacus：位置最後才寫** | v1 的 `commit` 每次都重寫整個最後一個 cluster，熱點的 cluster 上萬個 cells → O(n²) |
| **Abacus：(b) cost 有工作量上限** | (b) 要把被合併的 cells 一個一個走過。累計走了 1e9 個之後，合併超過 16 個 cell 就改用上界（每個 cluster 整串平移 \|shift\|，位移變化 ≤ \|shift\| × cell 數）。用「數 cell」不用「看時間」，結果不受機器快慢影響；ibm 只走了幾百萬個，所以 ibm 的結果和 v1 完全一樣 |
| **微調：heap 找最大** | 參考解每次都掃全部 cells 找位移最大的，100 萬 cell × 上萬次 = 太慢；改成 priority queue（位移變了就再推一個，過期的拿出來時丟掉） |
| **微調：evict 只看附近** | 每個 segment 只看 c 目標兩邊各 16 個 cell，不是 window 裡全部 |
| **微調：時間上限** | Abacus 做完後最多用剩下時間的 30%，`reduceMax` 每一步、`reduceTotal` 每 64 個 cell 檢查一次 |
| **SA：時間從 `anneal()` 進來就算** | 100 萬 cell 光是建 CSR、算每條 net 就要幾秒 |
| **SA：第一個溫度就照速度決定步數** | 估 T0 時順便量速度；v2 要做完第一個溫度才知道，L2 的第一個溫度就會把時間用光 |
| **SA：每個溫度的步數可以再變多** | 估的速度通常偏慢（一開始 cache 是冷的）；v2 只會往下調，只往下調的話，L2 的 SA 只用了 10 秒裡的 3.3 秒 |
| **SA：步數不夠就從低溫開始** | 時間只夠每個 cell 做不到 500 次 move（L1 約 200、L2 幾十）時 p0 改成 0.05：高溫把 placement 打亂後，沒有足夠的步數收回來 |

## 觀察

- **最大位移由熱點決定：** ibm01 微調到最後，有幾百個 cell 的位移卡在最大值附近（像一道牆）：熱點裡的 cells 要一起往外移才能再降，
  一次只動一兩個 cell 的 local move 做不到。L1 的最大位移少了一半（117,644 → 59,194），但微調是被時間切斷的，還沒收斂。
- **位移和 HPWL 是不同目標：** 微調讓總位移少 26%，legal HPWL 卻從 87.3M 變 90.9M（ibm01）：cells 被拉回 GP 附近，但不一定是 net 最短的地方。
  SA 之後兩者差不多（60.3M vs 60.0M），所以 Stage 1 只要專心壓位移。
- **大設計的瓶頸是時間：** L2 光讀檔就 3.9 秒，SA 只剩 22 秒（每個 cell 只有幾十次 move），所以 HPWL 只降 10%（ibm01 降 34%）。
  要再好就要讓每一步更快（多執行緒、更好的資料結構），或用比 SA 更有效率的局部最佳化（v4、v5 做的事）。
- **期限留了 10 秒：** 實測最久 49.4 秒；評分機如果比較慢，`--deadline` 也會讓各階段等比縮短（時間是邊跑邊量的，不是寫死的步數）。
  讀檔和 Abacus 不能中斷，是唯一無法縮短的部分（L2 合計約 15 秒）。
