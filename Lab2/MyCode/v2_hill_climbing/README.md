# v2 — Hill Climbing（爬山法）

> 第 4 課。在 v1 的合法樹上加入**最佳化**：隨機修改樹，分數沒變差就保留。

## 編譯與執行

```bash
cmake -S . -B build
cmake --build build
./build/cbi INPUT_FILE OUTPUT_FILE
```

stdout 會印出 `T_max: X, T_min: Y, Score: Z`，stderr 會印出各階段的 `[stage1]`、`[stage2]` 紀錄。

## 測資說明

| 代號 | 資料夾 | 內容 |
|---|---|---|
| **測資 A** | `Lab2/Testcases/testcases/` | 課程 15 筆（001 = 範例，002–015 從 1 到 10000 個 sinks） |
| **測資 B** | `Lab2/Testcases/holdout/` | 報告用的新測資 12 筆（5 到 10000 個 sinks，`w_skew` 1～10） |

Score = buffer cost + w_skew × skew，**越低越好**。數字來自 `Lab2/Report/`（`run_everything.sh`），全部通過 TA verifier（VALID）。

## 和 v1 相比改了什麼

v1 建完樹就結束；v2 多了一個 Stage 2：在時間內不斷對樹做小修改。

```
重複直到時間到：
    隨機對樹做一個小修改（move）
    如果修改後不合法 → 還原
    如果 Score 沒有變差 → 保留
    否則 → 還原
```

### 三種 move

| Move | 機率 | 做什麼 | 為什麼有用 |
|---|---:|---|---|
| **Pad**（插繞路 buffer） | 20% | 在某個節點和它的 parent 中間插一個新 buffer | 讓太早到的 sink **故意繞遠路**，拉高 T_min、縮小 skew |
| **Shift**（移動 buffer） | 40% | 隨機挑一個 buffer，往隨機方向移動 1、2、4、8…格 | 調整距離，讓各 sink 的到達時間更接近；小步微調、大步跳出死胡同 |
| **Reparent**（換 parent） | 40% | 把節點換到「祖父」或「parent 的兄弟」底下；舊 parent 沒有 children 就**刪掉** | 刪掉 buffer 直接省 cost |

### 怎麼保證全程合法

每個 move 改完之後，**只檢查被改到的節點**（`nodeOK`），不用整棵檢查：

- **Shift：** 只有被移動的 buffer 和它的 parent 的線長會變。
- **Reparent：** 只有新 parent 多了一個 child；舊的那邊只會變少，不會變不合法。
- **Pad：** 只有新 buffer 和原本的 parent 會變。

不合法就馬上還原，所以樹**隨時都是合法的**。最後 `main` 再用 `evaluate` 從頭完整檢查一次，萬一有問題就退回 v1 的樹，**絕對不會交出不合法的檔案**。

### 程式裡新增的部分

| 位置 | 內容 |
|---|---|
| `Tree::removeBuffer` | 不從 vector 拿掉（否則編號會錯位），而是標成 `DEAD`、釋放座標、把編號放進 `free_`；下次 `addBuffer` 優先重用 |
| `Tree::revive` | Reparent 失敗要還原時，把刪掉的 buffer 救回來 |
| `evaluate` | 跳過 `DEAD` 節點 |
| `nodeOK` | 只檢查單一節點的 fanout / length / 位置 |
| `quickScore` | 從 SRC 走一次整棵樹算 Score（O(N)） |
| `optimize` | 上面的 hill climbing 迴圈 |
| 時間 | `min(20, 2 + N/500)` 秒，離 60 秒限制很遠 |

`write` 不用改：它從 SRC 做 BFS，`DEAD` 的節點沒接在樹上，自然不會被寫出去。

## 觀察

- **每一筆都進步（或持平）：** 測資 A 幾何平均降到 v1 的 **0.630**，測資 B 降到 **0.452**，是五個版本裡進步幅度最大的一步。014 只有 1 個 sink，本來就是最佳解。
- **主要是降 skew：** 例如 A-004 從 cost 494 / skew 631 變成 cost 394 / skew 100；A-010 的 skew 從 4250 降到 1808。
- **Pad 對小測資特別有效：** A-002 從 119 降到 56、A-015 從 143 降到 113，主要都是靠插繞路 buffer 拉高 T_min。
- **弱點：卡在局部最佳。** Hill climbing 只接受「不變差」的修改，走到「往哪走都會變差」的地方就出不去。A-006（2208）離參考解（763）還很遠。下一版 v3 用模擬退火解決。
