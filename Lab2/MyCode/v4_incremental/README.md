# v4 — 增量計算 + 關鍵路徑（Incremental SA）

> 第 6 課。演算法和 v3 一樣是模擬退火，但每次修改不再重算整棵樹，**同樣時間可以多試 3～27 倍**；另外讓部分 move 對準決定 skew 的路徑。

## 編譯與執行

```bash
cmake -S . -B build
cmake --build build
./build/cbi INPUT_FILE OUTPUT_FILE
```

stdout 會印出 `T_max: X, T_min: Y, Score: Z`，stderr 會印出各階段的 `[stage1]`、`[stage2]` 紀錄。

## 和 v3 相比改了什麼

### 問題：每次都重算整棵樹太浪費

v3 每試一次修改，`quickScore` 都從 SRC 走完整棵樹（O(N)）。但移動**一個** buffer 時，真正會變的只有它自己和它的祖先，其他幾千個節點完全沒變。

### 解法：每個節點記住「子樹的摘要」

| `Node` 新欄位 | 意思 |
|---|---|
| `lo` / `hi` | 從這個節點往下，到子樹裡 sink 的**最短 / 最長**路徑 |
| `cnt` | 子樹裡有幾個 sink |
| `s1` / `s2` | 子樹裡所有 sink 路徑長的**總和 / 平方和**（用來算 σ） |
| `sumLen` | 到所有 children 的距離總和 |
| `type` | 目前最便宜的合法型號 |

**整棵樹的答案就在根節點上：** T_max = `nodes[0].hi`、T_min = `nodes[0].lo`，σ 由根的 `cnt`、`s1`、`s2` 算出，cost 由 `total_cost_` 隨時維護。所以 `T.score()` 只要 **O(1)**。

### 由 children 算出自己（`recompute`）

對每個 child c，邊長 e = d(自己, c)：

```
lo  = min( e + c.lo )
hi  = max( e + c.hi )
cnt = Σ c.cnt
s1  = Σ ( c.s1 + c.cnt × e )                 ← c 底下每個 sink 都多走 e
s2  = Σ ( c.s2 + 2e × c.s1 + c.cnt × e² )    ← (a+e)² = a² + 2ae + e²
```

### 往上更新，而且會提早停（`refreshUp`）

```cpp
void refreshUp(int v) {
    while (v >= 0) {
        if (!recompute(v)) break;   // 摘要沒變 → 祖先也不會變，停
        v = nodes_[v].parent;
    }
}
```

複雜度從 O(N) 變成 **O(深度 × fanout)**。`link`、`unlink`、`moveTo`、`removeBuffer`、`revive` 都會**自動呼叫 `refreshUp`**，`recompute` 和 `refreshUp` 放在 `private`，外面的程式不可能忘記更新。退火拒絕修改時只要做反向操作，摘要就自動回到原值。

### 安全檢查

增量寫錯的話分數會悄悄算錯，所以 `main` 每次最佳化後都比對：`evaluate`（完整 BFS 重算）和 `T.score()`（增量）**必須一模一樣**才採用，否則退回之前的解。

### 對準關鍵路徑（`criticalNode`）

有了 `lo` / `hi`，就能從 SRC 往下一路跟著「`e + child.lo == 自己.lo`」的 child 走，直接找到**決定 T_min 的路徑**（T_max 也一樣）。**30% 的 move 改成從這條路徑上挑節點**：Pad 對準最早到的路徑讓它繞路；Shift / Reparent 對準最早或最晚的路徑。skew 只由這兩條路徑決定，隨機挑的話大部分 move 根本碰不到它們。這一項讓整體再好約 5%。

### 其他

- 小測資（N ≤ 50）仍然用退火加 4 次重啟。曾測試改用 hill climbing，結果較差，所以保留。
- 時間上限和 v3 相同：`min(20, 2 + N/500)` 秒。

## 觀察

- **大測資進步最多：** A-010 從 32224 降到 22266（−31%），B-010 從 20226 降到 11470（−43%），B-005 從 1430 降到 859（−40%）。這些都是 w_skew 大（10）的測資，skew 降低的效果被放大。
- **A-011（1 萬 sinks）追平參考解：** 33248，參考解為 33114。
- **小測資本來就收斂了：** A-001～003、A-012 的差異在隨機性範圍內（A-003 從 163 變 177 是退火的運氣）。
- **整體：** 幾何平均比值 A 為 **0.936**、B 為 **0.823**。B 的大測資比例較高，所以進步更明顯。
