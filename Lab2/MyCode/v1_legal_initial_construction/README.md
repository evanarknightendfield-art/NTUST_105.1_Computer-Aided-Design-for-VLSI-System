# v1 — 初始合法時脈樹建構（Legal Initial Construction）

> 第 3 課。第一個**可以交**的版本：只求建出合法的樹，還不做任何最佳化。

## 編譯與執行

```bash
cmake -S . -B build
cmake --build build
./build/cbi INPUT_FILE OUTPUT_FILE
```

stdout 會印出 `T_max: X, T_min: Y, Score: Z`，stderr 會印出各階段的 `[stage1]`、`[stage2]` 紀錄。

| 代號 | 資料夾 | 內容 |

## 這一版做了什麼

在骨架（`my_cbi_skeleton`）的讀檔、`Tree`、`evaluate`、`write` 之上，加入**由下往上分群**的建樹演算法，讓程式自己建出一棵一定合法的 buffer 樹。

### 演算法：由下往上分群

把所有 sinks 一層一層「打包」：

```
第 1 輪：  S1 S3   S2 S4 S5   S6 S7 ...      ← 相鄰的 sinks 分成一群
            \/       \|/       \/
           buf      buf       buf           ← 每群放一個 buffer 當 parent
第 2 輪：   buf  buf  buf  ...               ← 這些 buffer 變成下一輪要分群的對象
              \   |   /
               buf
...
最後：         SRC                          ← 剩下的少到 SRC 接得住，就接上 SRC
```

**`frontier`**（前線）＝「目前還沒有 parent 的節點」。一開始是所有 sinks，每一輪：

1. **SRC 接得住嗎？** 數量 ≤ SRC 的 fanout，而且到 SRC 的距離總和 ≤ SRC 的 length，就全部接上 SRC，結束。
2. **排序：** 依 Morton 順序排序，讓空間上相鄰的點排在一起。
3. **貪心分群：** 一群一直加下一個點，直到「找不到合法的 buffer 位置」為止。
4. **放 buffer：** 每群（≥ 2 個點）放一個 buffer 當 parent，新 buffer 進入下一輪；只有 1 個點的群直接留到下一輪。
5. **都合不起來時：** 幫每個點往 SRC 方向插一個 **relay buffer**，讓它更靠近 SRC，下一輪再試。

### 四個關鍵技巧

| 技巧 | 做法 | 為什麼 |
|---|---|---|
| **Morton（Z-order）排序** | 把 x、y 的二進位位元交錯成一個數字再排序 | 只按 x 排序會把「x 近、y 很遠」的點排在一起；Morton 讓「排序後相鄰」≈「空間上相鄰」 |
| **buffer 放在中位數** | (x 的中位數, y 的中位數) | Manhattan 距離下，這是**總線長最短**的位置；連中位數都沒型號撐得住，其他位置一定也不行，可以直接放棄 |
| **螺旋找空位** | 中位數被佔用時，往外一圈一圈找（距離 1、2、…） | 第一個「在晶片內部、沒被佔用、有型號撐得住」的點就用它 |
| **佔用表** | `Tree` 裡的 `unordered_set` 記錄已佔用座標 | 查「這格有沒有人」只要 O(1)；`addBuffer`、`moveTo` 自動更新，外面不會忘記同步 |

### 為什麼一定會結束

每一輪一定發生兩件事之一：**有合併**（frontier 變少），或**沒合併**（每個點都被 relay 拉到嚴格更靠近 SRC 的位置）。數量和距離都不可能無限減少，所以迴圈一定會停。relay 也找不到位置（題目無解）時回傳 `false`，另外有 10 萬輪的上限當雙重保險。

## 觀察

- **全部合法、而且非常快：** 1 萬個 sinks 只要 0.02 秒。另外測了 283 筆極端測資（很小的晶片、很短的 L、很弱的 SRC），278 筆 VALID；失敗的 5 筆連最強的 AI 版本也建不出來，應該是題目本身無解。
- **分數偏高，主要來自 skew：** 建樹只求合法、不管到達時間。例如 001 的 skew 是 95（最佳解只有 1），010 的 skew 是 4250（cost 18294，但 w_skew = 10，skew 貢獻了 42500）。
- **下一步：** v2 加上最佳化，在合法的前提下調整樹的形狀來降低 skew 與 cost。
