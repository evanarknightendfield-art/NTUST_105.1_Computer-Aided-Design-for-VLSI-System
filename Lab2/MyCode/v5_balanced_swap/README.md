# v5 — 零 skew 合併點 + 結構調整（Balanced + Structural Moves）

> 依照課程講義（brief）找出的改進：零 skew 合併點、交換 parent，再加上合併 / 拆分 buffer、改接到較遠的鄰近 buffer、修正最佳解保存，時間上限放寬到 45 秒。**這一版就是交出去的 `M11502102`。**
>
> 舊版 v5（只有零 skew 合併點 + 交換 parent、40 秒）在 git commit `917e29a` 裡；新增的部分先在 `AI_Solutions/ClaudeOpus55_v6` 開發、測試後併回這裡。

## 編譯與執行

```bash
cmake -S . -B build
cmake --build build
./build/cbi INPUT_FILE OUTPUT_FILE [-t 秒數] [-s 亂數種子]
```

stdout 會印出 `T_max: X, T_min: Y, Score: Z`，stderr 會印出 `[stage1]`、`[optimize]`、`[stage2]` 紀錄。
`-t`、`-s` 是實驗用的選擇性參數，評分機只會給前兩個參數。

### (A) 零 skew 合併點：buffer 不再只放在中位數

v1～v4 把 buffer 放在 children 的**中位數**，這只讓總線長最短，完全不管到達時間。結果是某些 child 的子樹很早就到、某些很晚到，skew 從一開始就很大。

```
中位數（v1～v4）                零 skew 合併點（v5）
      B                                 B
     / \                               / \
   短   長                           長一點  短一點
   │     │                            │      │
  早到  晚到   → skew 大             同時到達      → skew 小
```

`balancedSpot` 在 children 的範圍內找一個位置，讓「各 child 子樹的到達時間（邊長 + child 的 `hi` / `lo`）最晚 − 最早」最小，同時考慮型號成本。這對應講義 L04 的 Tsay 零 skew 合併：合併點（tapping point）**不一定在中點**，要往延遲比較小的那一邊偏。

這個改動用在兩個地方：

- **建樹（Stage 1）：** 每群放 buffer 時改用 `balancedSpot`，所以**初始樹就比較平衡**。例如 A-004 的初始樹從 Score 1756（skew 631）變成 1070（skew 277）。
- **退火（Stage 2）：** 「重新放置」move 把某個 buffer 移到 `balancedSpot` 算出的位置。

### (C) 交換 parent

隨機挑兩個鄰近節點，**互換它們的 parent**。Shift 和 Reparent 一次只動一個節點，有些改善需要兩個節點同時換位置才做得到（一個移過去、一個移過來，fanout 不變）。這對應講義 L06 TimberWolf 的 interchange move，以及 L10 KL 演算法的成對交換。

### (D) Merge 與 (E) Split：改變 buffer 的數量和型號

v4 的 move 只能一次搬一個節點，很難把「一個很貴的 buffer」換成「兩個便宜的 buffer」，反過來也一樣。例如 A-009 的型號庫有 HUGE（fanout 16、成本 45），v4 常用它，cost 很高。

- **Merge：** 把鄰近 buffer `b2` 的所有 children 搬到 `v` 底下，刪掉 `b2`，一半機率再把 `v` 移到平衡位置。三分之一機率 `b2` 取 `v` 自己的 child，等於拿掉中間那一層。直接省下一個 buffer。
- **Split：** 從 `v` 的 children 中挑彼此靠近的一群，交給新的 buffer（放在 `balancedSpot`），新 buffer 接在 `v` 或 `v` 的 parent 底下。一個 HUGE 可以拆成 LARGE + 小型號，總成本反而更低。

### (F) 改接到較遠的鄰近 buffer

v4 的 Reparent 只能換到祖父或叔叔節點。`nearNode` 從節點往上走 1～3 層，再隨機往下走，可以找到樹上較遠、但空間上相近的 buffer（因為樹是依空間分群建的）。Reparent、Swap、Merge 各有一半機率用它。用 `isAncestor` 檢查不會形成環。

### (G) 修正最佳解保存

舊寫法只在每 1024 步檢查一次，把「當下的樹」存成最佳解；這時樹可能已經離開最佳狀態，所以存下的解可能比真正找到的最佳解差。現在找到更好的解時就保存（大型測資限制保存頻率，避免一直複製整棵樹）。

## 觀察

- **v1 → v5 累計：** 幾何平均比值 A 為 **0.409**、B 為 **0.258**。
- **改善最多的是中型測資和 `w_skew` 大的測資：** A-006 少 39%、B-010 少 38%。A-009 的改善主要來自 cost（Merge / Split 讓樹不再依賴昂貴的 HUGE）。
- **A-001 碰到理論下限：** 37 = cost 36 + skew 1。sink 的 arrival 奇偶性由座標決定（邊長奇偶 = 兩端 x+y 的奇偶差），這筆 sinks 的奇偶不一致，skew 不可能是 0。
- **大測資接近 cost 下限：** A-011 最終 Score / 下限 = 1.16、A-013 = 1.07。
- **執行時間：** 每筆 5～45 秒，最久的是 1 萬 sinks 的 45.05 秒，離 60 秒限制還有餘裕。
- **隨機性：** 同一版本每次跑的分數約有 ±1% 的差異（小測資可能更大），以上數字是 `Lab2/Report/results/` 裡那一次的結果。
