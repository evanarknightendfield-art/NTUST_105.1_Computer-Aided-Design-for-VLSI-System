# v5 — 零 skew 合併點 + 交換 parent（Balanced + Swap）

> 依照課程講義（brief）找出的兩個改進，加上把時間上限放寬到 40 秒。**這一版就是交出去的 `M11502102`。**

## 編譯與執行

```bash
cmake -S . -B build
cmake --build build
./build/cbi INPUT_FILE OUTPUT_FILE
```

stdout 會印出 `T_max: X, T_min: Y, Score: Z`，stderr 會印出各階段的 `[stage1]`、`[stage2]` 紀錄。

## 測資說明

| 代號 | 資料夾 | 內容 |
|---|---|---|
| **測資 A** | `Lab2/Testcases/testcases/` | 課程 15 筆（001 = 範例，002–015 從 1 到 10000 個 sinks） |
| **測資 B** | `Lab2/Testcases/holdout/` | 報告用的新測資 12 筆（5 到 10000 個 sinks，`w_skew` 1～10） |

Score = buffer cost + w_skew × skew，**越低越好**。數字來自 `Lab2/Report/`（`run_everything.sh`），全部通過 TA verifier（VALID）。

## 和 v4 相比改了什麼

| 改動 | 出處 | 程式裡的位置 |
|---|---|---|
| **(A) 零 skew 合併點** | L04：Tsay 零 skew 演算法、DME、GMA | 新函式 `balancedSpot`；`buildInitial` 建群時改用它 |
| **(A') 重新放置 move（10%）** | L04 | `optimize` 的 `move == 3` |
| **(C) 交換 parent move（10%）** | L06 TimberWolf interchange、L10 KL 成對交換 | `optimize` 的 `move == 4` |
| **Move 比例** | | Pad 20%、Shift 30%、Reparent 30%、重新放置 10%、交換 10%（原本 20 / 40 / 40） |
| **時間上限** | | `min(40, 2 + N/250)` 秒（原本 `min(20, 2 + N/500)`），限制是 60 秒 |

### (A) 零 skew 合併點：buffer 不再只放在中位數

v1～v4 把 buffer 放在 children 的**中位數**，這只讓總線長最短，完全不管到達時間。結果是某些 child 的子樹很早就到、某些很晚到，skew 從一開始就很大。

```
中位數（v1～v4）                零 skew 合併點（v5）
      B                                 B
     / \                               / \
   短   長                           長一點  短一點
   │     │                            │      │
  早到  晚到   → skew 大             同時到達      → skew 小
```

`balancedSpot` 在 children 的範圍內找一個位置，讓「各 child 子樹的到達時間（邊長 + child 的 `hi` / `lo`）最晚 − 最早」最小，同時考慮型號成本。這對應講義 L04 的 Tsay 零 skew 合併：合併點（tapping point）**不一定在中點**，要往延遲比較小的那一邊偏。

這個改動用在兩個地方：

- **建樹（Stage 1）：** 每群放 buffer 時改用 `balancedSpot`，所以**初始樹就比較平衡**。
- **退火（Stage 2）：** 新增「重新放置」move，把某個 buffer 移到 `balancedSpot` 算出的位置。

### (C) 交換 parent

隨機挑兩個鄰近節點，**互換它們的 parent**。Shift 和 Reparent 一次只動一個節點，有些改善需要兩個節點同時換位置才做得到（一個移過去、一個移過來，fanout 不變）。這對應講義 L06 TimberWolf 的 interchange move，以及 L10 KL 演算法的成對交換。

### 試過但沒有採用的

| 方法 | 出處 | 結果 |
|---|---|---|
| Range limiter（移動範圍隨溫度縮小） | L06 TimberWolf | 變差 0.4～0.7%；我們的移動距離本來就是 1、2、4…隨機混用 |
| H-tree、MMM | L04 | 要求 sink 分布均勻，或只做由上往下對半切 |
| DME 完整版、Elmore delay | L04 | 題目延遲是 Manhattan 距離加總，沒有 RC，且每個分支點都是要付錢的 buffer |
| Clock mesh、spine | L04 | 題目規定輸出必須是一棵樹 |

## 觀察

- **整體再好約 4%：** 幾何平均比值 A 為 **0.964**、B 為 **0.963**。v1 → v5 累計：A 為 **0.469**、B 為 **0.301**（分數不到初始建構的一半）。
- **大測資受惠於更多嘗試次數：** 40 秒加上更快收斂，1 萬 sinks 的嘗試次數 A-011 從 3420 萬增加到 6124 萬、B-012 從 4550 萬增加到 7569 萬。A-010 從 22266 降到 20446，A-011 從 33248 降到 32808，已經比參考解（33114）好。
- **A-001 碰到理論下限：** 37 = cost 36 + skew 1。sink 的 arrival 奇偶性由座標決定（邊長奇偶 = 兩端 x+y 的奇偶差），這筆 sinks 的奇偶不一致，skew 不可能是 0。
- **少數變差在隨機性範圍內：** A-005、A-012、B-004、B-005、B-006 稍微變差，幅度在 0.5～4%，和退火的隨機波動相當。
- **執行時間：** 每筆 2～40 秒，最久的是 1 萬 sinks 的 40.1 秒，離 60 秒限制還有餘裕。
